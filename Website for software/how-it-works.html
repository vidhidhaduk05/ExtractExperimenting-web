[ 01 ] HOW IT WORKS

A six-step pipeline,
designed to be auditable.

MetaSynthesis AI extracts data from the studies in your review and writes the result into an append-only workbook. Every value is linked back to a sentence in the source PDF, two independent extractors are run on every field, and a referee step flags disagreements before they reach you.

The tool is AI-assisted, human-verified. It is not a replacement reviewer and not a medical device. The TRIPOD-LLM validation study is in preparation; numbers below are framed as targets against published literature, not measured benchmarks.

[ 02 ] ARCHITECTURE

Two extractors, one referee,
one audited workbook.

Every field is extracted twice by independent prompts, then compared by a referee step that either accepts the agreed value, surfaces the disagreement for review, or rejects extraction when the source text is insufficient.

Extractor A

Primary pass

Reads the study, locates the field, returns a value plus the exact sentence(s) it was drawn from. Refuses to answer when no sentence supports the field.

Extractor B

Independent pass

Runs blind to A's output. Same prompt, separate context window. Same refusal behavior when evidence is missing.

Referee

Disagreement check

Compares A and B. Agreement is recorded. Disagreement is flagged as a human-review task with both candidate values and both source spans.

study.pdf  ─→  parse  ─→  Extractor A ─┬─→  Referee  ─→  workbook
                       ─→  Extractor B ─┘         │
                                                  └─→  human review (when flagged)
[ 03 ] THE PIPELINE

From PDF to a row in the workbook,
one auditable step at a time.

Each step writes to the workbook. Nothing is overwritten. Returning to a study a month later shows the same extractions plus any human edits, with timestamps.

  1. Step 01

    Define the protocol

    Upload your protocol or paste a PICO. Define the extraction schema: which fields, which units, which study-design constraints. Schemas can be saved and reused across reviews.

    Cochrane Handbook and JBI Manual templates are available as starting points. PRISMA 2020 reporting fields are pre-mapped.

    PICO Schema PRISMA 2020
  2. Step 02

    Ingest the study set

    Upload PDFs, point at a Zotero / EndNote / RIS export, or sync from a reference manager. The parser preserves page numbers, figure captions, table cells, and supplementary appendices.

    Files that fail to parse cleanly are quarantined rather than silently dropped. You see the list before extraction starts.

    PDF / RIS Tables preserved Quarantine on failure
  3. Step 03

    Dual extraction

    Two independent extractor passes (A and B) run on every field defined in your schema. Each pass returns the value plus the sentence(s) it was drawn from, or refuses if no sentence supports the field.

    Refusals are not failures. A refusal recorded with reason is more useful than a hallucinated number.

    Extractor A Extractor B Sentence-level provenance
  4. Step 04

    Referee + flag

    The referee compares A and B field-by-field. Agreement is written to the workbook with both source spans attached. Disagreement is logged as a review task with both candidate values, both spans, and a short summary of where they diverge.

    Disagreement rates per field are visible in the dashboard. Persistently divergent fields usually indicate a schema issue, not a model issue.

    Referee Disagreement log Inter-rater diagnostics
  5. Step 05

    Human review

    Review tasks open the source PDF at the cited sentence. You confirm, correct, or reject. Every edit is captured with the editor's identity, timestamp, and prior value. Nothing in the audit trail is overwritten.

    The reviewer is always the source of truth. The tool's output is a draft until a human signs the row off.

    Source-anchored Append-only audit Human in the loop
  6. Step 06

    Export + cite

    Export the workbook as CSV, XLSX, or RevMan-compatible JSON. Every cell carries its source span. A bundled report records model name, prompt version, schema version, and the full edit history for the review.

    The How-to-Cite section on the landing page provides BibTeX. The TRIPOD-LLM validation study, when published, will be the canonical reference for the pipeline's behavior.

    CSV / XLSX RevMan JSON Cite-ready report

What is not yet validated

None of the steps above carries a measured accuracy claim. We have internal targets drawn from Konet et al. (2024), Sun et al. (2024), and Khraisha et al. (2023), but the prospective TRIPOD-LLM study to test those targets on our own pipeline is in preparation. Until it is published, we describe per-field performance as aspirational.

If you need numbers right now to satisfy a funder or an IRB, the safe summary is: the pipeline is positioned to meet or exceed published accuracy targets on extraction tasks of comparable difficulty, and it is structured so that any miss is recoverable from the audit trail.

[ 04 ] COMPARED TO AD-HOC LLM EXTRACTION

Why not just use
a chat window?

A general-purpose LLM in a chat interface can pull values from a paper. It cannot, by default, prove which sentence a value came from, run a second blind pass, or refuse to invent a number when one is missing. Those are the parts that make a review defensible.
